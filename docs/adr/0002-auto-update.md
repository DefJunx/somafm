# Auto-update via the Tauri updater and GitHub releases

The app checks for new versions with `tauri-plugin-updater` and offers them in an Update banner. The signed update manifest `latest.json` and the `.sig` files are release assets on GitHub (`https://github.com/DefJunx/somafm/releases/latest/download/latest.json`), generated by the release workflow. The user is always asked: nothing installs silently and playback is never cut without consent.

This reverses the v1 non-goal "auto-update" ([v1 spec section 11](../../.scratch/somafm-v1/spec.md#11-out-of-scope)). Releases are now published on GitHub (see [ticket 06](../../.scratch/somafm-app/issues/06-third-party-policy-grilling.md)), so existing installs need a way to move forward.

## Consequences

- Updates are signed with a key from `tauri signer generate`. The private key and its password live as GitHub Actions secrets; the public key is in `tauri.conf.json`. Losing the private key means existing installs can never update and users must reinstall by hand, so an offline backup of the key is mandatory.
- Linux is notify-only: the Update banner links to the release page. The `tar.gz` + `install-linux.sh` flow cannot be updated in place by Tauri. An AppImage build would lift this and is a possible later ticket.
- macOS is included in the updater and is as unverified as the rest of macOS support (unsigned `.app`).
- Release notes shown in the banner come from the matching `CHANGELOG.md` section.
- The check runs on launch and every 24 h, gated by the "Check for updates automatically" setting (default on).
